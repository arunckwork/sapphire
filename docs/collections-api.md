# Collections API — Reference Documentation

> Intended audience: Backend engineers implementing the `/api/v1/collections` resource.
> Derived from the frontend collection feature redesign spec.

---

## Base URL

All routes are prefixed with `/api/v1`.

The Next.js frontend proxies these through BFF routes at `/api/collections/*`, forwarding the `access_token` cookie as a `Bearer` token.

---

## Data Models

### CollectionType

```
"single_stone" | "bulk_stones" | "jewellery" | "industrial_stones"
```

### SellerRef (embedded in response)

```json
{
  "id": "string",
  "first_name": "string",
  "last_name": "string | null",
  "email": "string"
}
```

### BulkStoneRow

```json
{
  "gemstone_type": "string (lowercase)",
  "variety": "string (lowercase)",
  "quantity": "integer ≥ 1",
  "weight": "decimal",
  "weight_unit": "string (lowercase, e.g. ct, g, ratti)"
}
```

---

### Collection Object

Each collection shares a **common base** plus type-specific fields.

#### Common Base Fields (all types)

| Field               | Type                   | Description                                      |
|---------------------|------------------------|--------------------------------------------------|
| `id`                | `string` (UUID)        | Auto-generated by backend                        |
| `serial_no`         | `string`               | Auto-generated by backend (e.g. `COL-SNG-2026-001`) |
| `collection_type`   | `CollectionType`       | One of the four types                            |
| `seller_id`         | `string` (UUID)        | Reference to the seller (user with role=user)    |
| `seller`            | `SellerRef`            | Embedded seller info in responses                |
| `certification_no`  | `string`               | Certification number (optional)                  |
| `certification_lab` | `string`               | Certification laboratory (optional, lowercase)   |
| `asking_price`      | `decimal`              | Asking price (required, > 0)                     |
| `images`            | `string[]`             | Array of image URLs (backend-managed)            |
| `created_at`        | `string` (ISO 8601)    | Auto-set by backend                              |
| `updated_at`        | `string` (ISO 8601)    | Auto-set by backend                              |

#### Type-Specific Fields

**`single_stone`**

| Field           | Type      | Required | Notes                        |
|-----------------|-----------|----------|------------------------------|
| `gemstone_type` | `string`  | Yes      | Lowercase (e.g. `"sapphire"`) |
| `variety`       | `string`  | No       | Lowercase or custom text     |
| `treatment`     | `string`  | No       | Lowercase constant or custom |
| `origin`        | `string`  | No       | Lowercase constant or custom |
| `weight`        | `decimal` | Yes      | > 0                          |
| `weight_unit`   | `string`  | Yes      | `"ct"`, `"g"`, or `"ratti"` |
| `shape`         | `string`  | No       | Lowercase constant or custom |
| `cut`           | `string`  | No       | Lowercase constant or custom |
| `color`         | `string`  | No       | Lowercase constant or custom |
| `clarity`       | `string`  | No       | Lowercase constant or custom |
| `dimensions`    | `string`  | No       | e.g. `"8.5 x 6.2 x 4.1 mm"` |

**`bulk_stones`**

| Field         | Type             | Required | Notes                        |
|---------------|------------------|----------|------------------------------|
| `stones`      | `BulkStoneRow[]` | Yes      | At least 1 row required (each stone row includes `gemstone_type`, `variety`, `quantity`, `weight`, `weight_unit`) |
| `description` | `string`         | No       | Free-text description        |

**`jewellery`**

| Field         | Type      | Required | Notes                        |
|---------------|-----------|----------|------------------------------|
| `weight`      | `decimal` | Yes      | Total weight of the piece, > 0 |
| `weight_unit` | `string`  | Yes      | `"ct"`, `"g"`, or `"ratti"` |
| `description` | `string`  | No       | Free-text description        |

**`industrial_stones`**

| Field         | Type      | Required | Notes                          |
|---------------|-----------|----------|--------------------------------|
| `stone_type`  | `string`  | Yes      | Lowercase constant or custom   |
| `variety`     | `string`  | No       | Lowercase or custom text       |
| `weight`      | `decimal` | Yes      | > 0                            |
| `weight_unit` | `string`  | Yes      | `"ct"`, `"g"`, or `"ratti"`   |
| `description` | `string`  | No       | Free-text description          |

## Endpoints

---

### 1. List Collections

```
GET /api/v1/collections
```

Returns a paginated list of all collections.

#### Query Parameters

| Parameter         | Type                    | Required | Default       | Description                          |
|-------------------|-------------------------|----------|---------------|--------------------------------------|
| `page`            | `integer ≥ 1`           | No       | `1`           | Page number                          |
| `limit`           | `10 \| 25 \| 50`        | No       | `10`          | Results per page                     |
| `search`          | `string`                | No       | `""`          | Search across serial_no, seller name |
| `collection_type` | `CollectionType`        | No       | —             | Filter by collection type            |
| `seller_id`       | `string`                | No       | —             | Filter by seller                     |
| `sort_by`         | `"created_at" \| "asking_price" \| "collection_type"` | No | `"created_at"` | Sort field |
| `sort_order`      | `"asc" \| "desc"`       | No       | `"desc"`      | Sort direction                       |

#### Response `200 OK`

```json
{
  "data": [CollectionObject],
  "total": 42,
  "page": 1,
  "limit": 10
}
```

---

### 2. Get Single Collection

```
GET /api/v1/collections/:id
```

#### Path Parameters

| Parameter | Type     | Description          |
|-----------|----------|----------------------|
| `id`      | `string` | Collection UUID      |

#### Response `200 OK`

Returns a single `CollectionObject`.

#### Error Responses

| Status | Condition           |
|--------|---------------------|
| `404`  | Collection not found |

---

### 3. Create Collection

```
POST /api/v1/collections
Content-Type: multipart/form-data
```

> **Note:** Images are sent as multipart file fields. All other fields are sent as form string values.

#### Authorization

Bearer token required. Caller must have role `admin` or `manager`.

#### Request Body (multipart/form-data)

**Common fields (all types):**

| Field               | Type            | Required | Notes                                |
|---------------------|-----------------|----------|--------------------------------------|
| `collection_type`   | `string`        | Yes      | One of the four type values          |
| `seller_id`         | `string` (UUID) | Yes      | Must be a user with `role = user`    |
| `certification_no`  | `string`        | No       |                                      |
| `certification_lab` | `string`        | No       | Lowercase                            |
| `asking_price`      | `decimal`       | Yes      | > 0                                  |
| `images`            | `File[]`        | No       | Multiple image files                 |

**`single_stone` additional fields:**

| Field           | Type      | Required |
|-----------------|-----------|----------|
| `gemstone_type` | `string`  | Yes      |
| `variety`       | `string`  | No       |
| `treatment`     | `string`  | No       |
| `origin`        | `string`  | No       |
| `weight`        | `decimal` | Yes      |
| `weight_unit`   | `string`  | Yes      |
| `shape`         | `string`  | No       |
| `cut`           | `string`  | No       |
| `color`         | `string`  | No       |
| `clarity`       | `string`  | No       |
| `dimensions`    | `string`  | No       |

**`bulk_stones` additional fields:**

| Field               | Type     | Required | Notes                              |
|---------------------|----------|----------|------------------------------------|
| `stones`            | `string` | Yes      | JSON-encoded `BulkStoneRow[]`      |
| `description`       | `string` | No       |                                    |

> **Implementation note:** Since multipart doesn't support nested JSON natively, `stones` is sent as a JSON string and must be parsed server-side.

**`jewellery` additional fields:**

| Field         | Type      | Required |
|---------------|-----------|----------|
| `weight`      | `decimal` | Yes      |
| `weight_unit` | `string`  | Yes      |
| `description` | `string`  | No       |

**`industrial_stones` additional fields:**

| Field         | Type      | Required |
|---------------|-----------|----------|
| `stone_type`  | `string`  | Yes      |
| `variety`     | `string`  | No       |
| `weight`      | `decimal` | Yes      |
| `weight_unit` | `string`  | Yes      |
| `description` | `string`  | No       |

#### Response `201 Created`

Returns the newly created `CollectionObject` with backend-generated `id`, `serial_no`, `created_at`, and `updated_at`.

#### Error Responses

| Status | Condition                        |
|--------|----------------------------------|
| `400`  | Validation error (missing fields, invalid type) |
| `401`  | Unauthenticated                  |
| `403`  | Insufficient role                |
| `404`  | `seller_id` user not found or not role=user |

---

### 4. Update Collection

```
PUT /api/v1/collections/:id
Content-Type: multipart/form-data
```

Same request body as Create. `serial_no` and `collection_type` are **immutable** after creation — backend should ignore or reject changes to them.

#### Response `200 OK`

Returns the updated `CollectionObject`.

#### Error Responses

| Status | Condition              |
|--------|------------------------|
| `400`  | Validation error        |
| `401`  | Unauthenticated         |
| `403`  | Insufficient role       |
| `404`  | Collection not found    |

---

### 5. Delete Collection

```
DELETE /api/v1/collections/:id
```

#### Response `204 No Content`

#### Error Responses

| Status | Condition              |
|--------|------------------------|
| `401`  | Unauthenticated         |
| `403`  | Insufficient role       |
| `404`  | Collection not found    |

## Sellers List (for autocomplete)

```
GET /api/v1/users?role=user
```

Returns a list of users with `role = user` (sellers). Same pagination and query params as the [Users List API](./users-list-api.md). The frontend uses this to populate the Seller autocomplete dropdown.

> **Alternative:** A dedicated `/api/v1/sellers` endpoint returning a minimal `[{ id, first_name, last_name, email }]` list without pagination — suitable for autocomplete if the user count is manageable.

---

## Serial Number Convention

Serial numbers are auto-generated by the backend on creation. Suggested format:

| Collection Type    | Prefix   | Example                 |
|--------------------|----------|-------------------------|
| Single Stone       | `SNG`    | `COL-SNG-2026-001`      |
| Bulk Stones        | `BLK`    | `COL-BLK-2026-002`      |
| Jewellery          | `JWL`    | `COL-JWL-2026-003`      |
| Industrial Stones  | `IND`    | `COL-IND-2026-004`      |

---

## Dropdown Value Conventions

All dropdown/autocomplete string values are submitted in **lowercase** from the frontend. The backend should store and return them as-is (lowercase).

### Accepted values by field

| Field             | Source Constant           | Example values (lowercase) |
|-------------------|---------------------------|---------------------------|
| `gemstone_type`   | `GEMSTONE_TYPES`          | `"sapphire"`, `"ruby"` |
| `variety`         | `GEMSTONE_VARIETIES`      | `"blue sapphire"`, custom |
| `treatment`       | `TREATMENT_OPTIONS`       | `"none / unheated"`, `"heat treated"` |
| `origin`          | `ORIGIN_OPTIONS`          | `"sri lanka (ratnapura)"` |
| `weight_unit`     | `WEIGHT_UNITS`            | `"ct"`, `"g"`, `"ratti"` |
| `shape`           | `SHAPE_OPTIONS`           | `"cushion"`, `"oval"` |
| `cut`             | `CUT_OPTIONS`             | `"excellent"`, `"step cut"` |
| `color`           | `COLOR_OPTIONS`           | `"royal blue"`, custom |
| `clarity`         | `CLARITY_OPTIONS`         | `"vvs1 (very very slightly included 1)"` |
| `certification_lab` | `CERTIFICATION_LABS`    | `"gia (gemological institute of america)"` |
| `stone_type`      | `INDUSTRIAL_STONE_TYPES`  | `"abrasive corundum"`, custom |
| `collection_type` | Fixed enum                | `"single_stone"` etc. |

> Custom text inputs are also allowed for most fields (except `weight_unit` and `collection_type`).
